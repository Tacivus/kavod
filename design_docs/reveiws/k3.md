# Adversarial Review — `design-v12.md`

**Scope:** semantics of the design document only, reviewed self-standing against its own text (lines 1–1199). No other files consulted.
**Method:** eight parallel adversarial passes (Run state machine, latch/error linearization, determinism/trace, live environment, simulated environment, journal/records, document meta-rules, time/index semantics), each instructed to attempt refutation before reporting. ~60 candidate breaks were generated; roughly a third survived refutation. Findings below are deduplicated and re-classified after cross-checking the overlapping reports against the text.

**Severity legend:** **CONTRADICTION** — two normative statements collide (or a statement collides with the document's own meta-rules). **GAP** — required content is missing where the document claims completeness. **AMBIGUITY** — consistent outcomes, but two readings exist and the text doesn't adjudicate. **NIT** — cosmetic/minor.

---

## 1. Contradictions

### C1 — A9 (Determinism) is falsified by the design's own Error erasure
- **Sites:** A9 (L148): *"every run output is a function of the build, the Application, its initial State, the configuration, and the trace."* Trace (L126–128): *"with Error values erased and their presence and position kept."* `EngineExit::Fatal` carries `EE`/`AE` values (L594–613); `JournalError::Sink` wraps `std::io::Error` (L500).
- **Break:** Two runs with identical (build, Application, State, config, trace) can exit with *different* Environment/sink Error values — those values are erased from the trace by definition and supplied by nothing else. DET-RUN (L745) already concedes this (*"equal outright **when** the Error values erased from the trace also correspond"*), but the axiom never does. The exit is *"the run's only outcome channel"* (L727), so "run output" can't exclude it.
- **Fix:** scope A9's "run output" to Core-owned content, or append "modulo erased Error values" — exactly the hedge DET-RUN already carries.

### C2 — The Glossary's "Accepted" collides with three binding texts
- **Sites:** Glossary (L87–88): *"Accepted — a candidate whose `EventAccepted` record committed; **only then** does it have an index"* (a Candidate is *"an Event returned by `next_event`"*, L86). Against it: the Records table (L720, binding): `RunStarted` evidences *"**Acceptance** of the start turn, index 0"*; the `EventIndex` doc (L210, binding): *"The **accepted** turn's ordinal: 0 for the start turn"*; the `Context::index` doc (L257, binding): *"The current **accepted** turn"* — false during `on_start` under the Glossary reading.
- **Also folded in:** RUN-INDEX's *"the accepted **count**: 0 for the start turn"* (L742, L758) vs. the doc's "**ordinal**" — after the start turn, one turn is accepted but the index is 0; the index counts accepted *external* events, not accepted turns.
- **Fix:** redefine as "a turn whose acceptance record (`RunStarted` or `EventAccepted`) committed," and pick one of count/ordinal.

### C3 — `PORT-ROUTING` names both shipped implementations inside a Core contract row
- **Sites:** `PORT-ROUTING` (L344): *"…at that Environment's own mapping site — **sim: the fan-out arm; live: supervision** — placed finally when Wiring closes."* Section 0 (L52–55): *"Core sections build only on the contracts and **never name an implementation** — earlier mentions … are navigation only (the Scope line, the contract's pointer to its implementations, the bounds registry)."*
- **Break:** the parenthetical reads as an exhaustive list of permitted implementation mentions; `PORT-ROUTING`'s "sim:/live:" is a fourth, and it's *normative* (it assigns mapping sites), not navigation. It falsifies the "navigation only" claim and is simultaneously a non-exempt forward reference. The content had a legal home — section 10 repeats it at L1083–1087.
- **Fix:** move the per-implementation mapping-site assignment to Wiring (or an implementation section) when Wiring closes.

### C4 — `RUN-CHECKPOINT`'s "exactly once" vs. the Stop path's second latch observation *(borderline AMBIGUITY)*
- **Sites:** RUN-CHECKPOINT (L743): *"Every turn that reaches `EffectsComplete` takes the latch snapshot (`take_error`) **exactly once**"* — then, same row: *"on the Stop path the next and final latch **observation** is shutdown's close."* ENV-LATCH (L450) and the `ShutdownReport` doc (L417–419) treat the close as an observation.
- **Break:** a Stop turn reaching `EffectsComplete` observes the latch twice (snapshot + close). The row survives only if "snapshot" and "observation" are different categories — but the row itself uses "observation" for both. This is observation-count-dependent determinism vocabulary (DET-ENV compares *"the report's Error presence"*), so it's not purely cosmetic.
- **Fix:** one clause: "exactly one `take_error` per turn; the close is a separate, final observation."

## 2. Gaps

### G1 — `Certificate::last_time` is never written by any binding row ⚠️ *the most substantive finding*
- **Sites:** Certificate fields (L759): `last_time: Timestamp, // the last accepted logical time`. Startup table step 3 (L658): mint *"consuming the Journal"* — nothing else. `run_started(start_time)` transition "Does" column (L776): literally *"—"*. Enforcement prose (L796–797): only the *index* *"becomes the certificate's on success."* Presupposed by: RUN-GRAMMAR (L740), `Context::logical_time` (L259: *"the start time at index 0"* via the certificate getters, L766–767), and the `EventAccepted` edge's regression check (L710), whose `previous` for the first external event *must* be the frozen start time.
- **Break:** the tables are declared exhaustive (*"work it does not list does not happen"*, L25), yet no listed work initializes `last_time` to the start time or updates it on `accept_event` success. A literal reading of the document's own discipline produces a certificate with uninitialized time at index 0 — skipping the first `TimeRegression` baseline and breaking the `logical_time()` guarantee at index 0. Behavior is derivable, so no implementer is truly stuck — but the hole sits exactly where completeness is claimed. Must be closed before implementation.

### G2 — The clean report's retention across a failed `TurnCompleted(Stop)` commit is unstated
- **Sites:** `close(env)` transition (L782) assigns Fatal-path consumption only to *"a report of `Some` or `Incomplete`"*; the clean-report-plus-commit-failure case is unnamed. RUN-FINALIZE (L744) says *"consumed, exactly when `StopPending` ran → reuse that report"* — but no row establishes the report survives the failed commit so FINALIZE can reuse it. Under L25's exhaustiveness rule, that retention is work no table lists.

### G3 — The premature-closure typed Error has no defined value in the closed spec
- **Sites:** LIVE-SUPERVISION (L917) binds publication of *"a typed Error"* when `run` returns `Ok(())` while `Running` — but no Port Error value exists in that case, and `PORT-ROUTING` only maps *existing* Port Errors. The carrying variant ("premature closure") exists only in the *open* Wiring section (L1083–1087). A closed, enforced guarantee depends on open-section content — a forward dependency the placement rules don't license. Tempered: section 10 does name the variant, so this is queued for the Wiring close-out, not a design hole.

### G4 — "Mechanism" is a fifth document category the meta-rules never classify
- **Sites:** Section 0: four binding forms + prose with three jobs (L14–36), *"a rule in none of the four forms does not exist."* But the Application (L279), Journal (L517), and Sim (L1033) Mechanism sections and the Enforcement section (L750) are unhedged; only Live's mechanism disclaims (*"One workable mechanism, replaceable wherever the guarantees hold"*, L924). Section 11 uses "mechanism" as if defined (L1108). If mechanism binds, the four-forms rule has a hole; if it's prose, much of it fails the deletion test (e.g., *"The reusable bounded buffer implements `std::io::Write`…"*, L519, does none of define/derive/justify).

### G5 — `RUN-GRAMMAR` incorporates Enforcement through a citation form the rules don't license
- **Sites:** RUN-GRAMMAR (L740): *"…work its own transition performs **(Enforcement)**. The residue that stays runtime is listed there."*; echoed at L1099. Section 0 licenses citations as IDs, binding-table names, or exempt navigation pointers — "(Enforcement)" is none of these, the transition table is absent from the binding-table list (L23–25), and the citation points *forward* within the section. The document's flagship enforced guarantee pulls normative content through a formless reference. Fix: give the transition table binding-table status (and a name/ID) in L23–25.

### G6 — Sim: two `next_event` Err paths never name their subordinate effects
- **Sites:** the commitment table (L438) sanctions Err-side effects only as *"subordinate effects the implementation names"*; SIM-SELECT (L1028) names them for `step(Err)` only. Mid-selection SIM-COMPLETION (L1030) and SIM-STEPS exhaustion (L1029) after prior `step(None)`s carry the same effects (advanced `now`, cleared arms, spent budget, Port mutations) and name nothing. Behaviorally nil (ENV-SERIAL permits only `shutdown` afterward), but the document's own idiom makes naming the sanction mechanism — one shared clause closes it.

### G7 — `PORT-ROUTING`'s sim Error mapping site is wrong for two of three Port-Error sources
- **Sites:** L344 names *"sim: the fan-out arm"* — but `start(Err)` (SIM-START) and `step(Err)` (SIM-SELECT) never pass through the fan-out match. Only `on_command(Err)` does. The open Wiring item inherits the defective pointer (L1085–1087). When Wiring closes, the sim sites must be enumerated as start/step/fan-out-arm.

### G8 — The sim replay "three preconditions" don't cover failure runs
- **Sites:** L1060–1063. Byte-equal replay of a run that ended via latched Port Errors, `step(Err)`, a start-Err (empty Journal, L1066), or sink failures requires replay Ports *and* the sink to reproduce each recorded failure presence at its trace position — nothing in the three preconditions says so. Exactly the failure-forensics runs where replay matters most. Also: *"the replay Port"* is singular; multi-Slot recordings need one replay Port per recorded Slot. Fix: scope to failure-free runs or add the fourth precondition.

### G9 — `CommandBoundExceeded` destroys the turn's intent with zero evidence, unnamed
- **Sites:** L688 (discard), L639 (bare `CoreError` variant — no count, no payload), Trace definition (L126–130 — staged Commands appear nowhere). Unlike the precisely parallel abort case (L854–856) and discarded-`Fatal`-payload case (L688), whose evidence consequences the doc *does* name, the overflow path's evidence vacuum is never stated. The run dies with the acceptance record as the last byte and no way to reconstruct what the handler tried to stage. One derive-note closes it.

### G10 — `NO-UNWIND`'s no-reliance half fits none of the three licensed enforcement means
- **Sites:** L57–58 (unrepresentable / asserted / tested) vs. `NO-UNWIND` (L170): `catch_unwind` compiles under `panic = "abort"`, no assertion exists, and no convention in L1159–1180 pins it. The profile half is trusted (`TRUST-ABORT` ✓); the no-reliance half has only review — a means section 0 grants obligation rows, not enforced ones.

### G11 — Observation-vs-cause documentation never reaches the API surface
- **Sites:** `EnvironmentFatal` (L610–613) presents a bare `error` field; only the `NextEvent`/`Dispatch` *variant* docs (L619–623) hint the Error may be *"an unrelated already-latched Error"*; the `Prepared` row's gloss (L689: *"the Command at k was not handed off"*) reads naturally as "attempted and rejected," which is false when the loop stopped to observe a *previous* Command's latched publication (sim: `on_command(Err)` at k → `Dispatch { position: k+1 }`, L1026/L1037–1040). The Notes (L831–835) concede observation-vs-cause, but `TRUST-KEY` reconciliation reads the exit, not the Notes. Fix: one clause in the `Prepared` row + a struct-level doc on `EnvironmentFatal`.

### G12 — The Glossary is missing from the forward-reference exemption list
- **Sites:** L44–47 exempts five navigation structures; the normative Glossary (L70) necessarily defines terms via later-bound items (`Candidate` → `next_event` §5; `Accepted` → `EventAccepted` §7; `Handoff` → `dispatch` §5; `Trace` → §5; `Phase, edge, certificate` → §7). The parallel invariant index is exempted; the Glossary's omission leaves every front-loaded definition technically out of rule.

## 5. Attacks that failed — where the design proved robust

These were serious attempts that the text defeated; they are evidence of strength:

- **`RUN-INDEX` arithmetic is sealed.** `BetweenTurns` is the sole predecessor of `accept_event`; the `u64::MAX` guard runs before `next_event`; the last legal increment is MAX−1→MAX; the "overflow past that check" panic is unreachable by construction. Commit failure leaves the index un-advanced with the certificate dropped.
- **`SIM-TIME`'s invariant holds.** Arms are always ≥ `now` (checked at arming; selection takes the minimum, so `now` never passes any remaining arm; dispatch doesn't move `now`). The Zeno re-arm attack (`set_next(now)` forever): the step budget bounds the *acquisition* loop; cross-turn starvation of later arms is inherent min-time discrete-event semantics — deterministic, and bounded by the index domain. Defensible as designed.
- **The latch state machine is closed**, and the `take_error`/`ShutdownReport` doc asymmetry ("nothing was pending" vs. "empty or already reported") is *forced* by `ENV-SERIAL`, not accidental.
- **`ENV-LATCH`'s linearization paragraph survives all four operation×implementation pairs** — including the subtlest point in the document, the sim dispatch whose publication is *caused by* its own commitment (correctly "linearized after").
- **Every Run path complies with `ENV-SERIAL`** — including sim's dispatch-returns-`Ok`-after-publication (no restriction triggers on `Ok`; the *next* dispatch becomes the Err-returning operation).
- **Journal byte arithmetic is exact** across all three size regimes: object = `max` commits; `max`+1 dies at the newline step; > `max`+1 dies at zero-progress encode. The apparently redundant `Interrupted` clause in `JRN-POISON` is load-bearing (forbids the conventional retry-on-`Interrupted`). Poison taxonomy complete.
- **The wire format is internally consistent**: key order pinned ("in table order"), example matches, `schema_version`-on-`RunStarted`-only is sound, `JournalFatal`'s kind-only shape is provably sufficient.
- **The ID lattice is an exact bijection**: 53 enforced + 16 trusted IDs, each defined exactly once, Appendix A complete, no dangling citations.
- **All five "exhaustive" table claims survive line-by-line audit** (state, edge, record, commitment, construction tables); the unrepresentable/runtime-residue partition in `RUN-GRAMMAR` is clean; the Obligations table survives a determined hunt for homeless assumptions.
- **Trace sufficiency**: every handler- and Core-observable input closes under (build, Application, State, config, trace) — *except* the erased Error values, which is finding C1.
- **Sim Stop-path report is structurally `None`** — verified: no Port runs between checkpoint and close.
- **Certificate affinity admission is honest and test-covered**; golden-Journal tests carry what the type system can't.

## 6. Verdict and prioritized fixes

**Overall: the design is genuinely strong but not yet solid.** The behavioral core — graph, latch, commitment points, journal arithmetic, determinism *machinery* — survived every attack thrown at it; all four refutation-heavy passes (sim, journal, latch, run graph) independently reported the same thing: the mechanisms are consistent, and the failures concentrate at the *specification layer* — unnamed evidence holes, vocabulary collisions, and meta-rule self-violations — plus exactly one substantive bookkeeping gap.

**Must fix before implementation (semantic):**
1. **G1** — write `last_time` initialization/update into the binding tables (startup step 3 or `run_started`'s "Does", and `accept_event`'s success).
2. **C1** — scope A9's "every run output" to match DET-RUN's existing hedge.
3. **G2** — state the clean report's retention across a failed `TurnCompleted(Stop)` commit.
4. **A2/G9/G11** — name the three evidence holes (first-published Error discarded at finalization; overflow intent vacuum; observation-vs-cause at the API surface) at the doc's own honesty standard.

**Fix when Wiring closes (already queued there):**
5. **G3 + G7** — the premature-closure Error variant and the real sim mapping sites (start/step/fan-out-arm, not "the fan-out arm").
6. **C3** — move implementation names out of `PORT-ROUTING`.

**Fix in one editing pass (discipline):**
7. **C2** — repair "Accepted"/count/ordinal vocabulary across the Glossary, `EventIndex` doc, and Records table.
8. **G4 + G5** — declare Mechanism's status (one sentence per section, as Live already has) and give the Enforcement transition table binding status.
9. **C4, A1, A8, A12–A14** — the vocabulary/exemption clarifications.
10. **G8** — add the fourth replay precondition (failure-presence reproduction).

**Nits (N1–N12)** are each a one-line edit; batch them.

None of the 30+ findings requires a redesign — every fix is a sentence or a moved clause. But a document whose root rule is *"a rule in none of the four forms does not exist"* should not contain an undeclared fifth form (G4/G5), and a document that declares its tables exhaustive should not leave its certificate's clock unwritten (G1). Those two are the ones I'd be most embarrassed by — they're exactly the class of issue this document's discipline exists to prevent.
