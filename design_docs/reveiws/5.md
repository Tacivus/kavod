Six attack angles were run (five parallel agents + my own consistency pass after one agent returned empty twice; I re-verified every finding below against the text). The core held up remarkably well — but it is not airtight. Findings, ordered by severity:
Contradictions (falsifiable as written)
C1. DET-ENV is falsifiable by fully legal runs — the trace omits the handler Outcome. design_docs/design-v11.md:99,677
The trace = (Event, Timestamp) sequence + env-op results + sink-op results + Quiescence. It does not record handler Outcomes (Stop/Continue/Fatal/overflow). DET-ENV's only stated premise is "equal traces" (unlike DET-RUN, which also requires same build/Application/State/config). Constructions with equal traces and differing compared discriminants:
- App P's on_start answers Stop (empty batch → StopRequested commit fails at write) vs App Q's answers Continue (TurnCompleted(Continue) commit fails at write). Env ops (start Ok, take_error None, shutdown Quiesced) and sink ops (Ok,Ok,Err) identical → equal traces, but JournalFatal.record_kind = StopRequested vs TurnCompleted — a listed DET-ENV discriminant.
- on_start → Fatal(e) vs on_start overflow → Core(CommandBoundExceeded): zero env/sink ops either way → FatalCause variant differs.
- Encode vs BoundExceeded at step 2 (no sink op at all) → JournalError variant differs.
Fix is one sentence: DET-ENV must inherit DET-RUN's premise list. Intended semantics are fine; the written rule is not.
C2. "Records carry indices, times, Events, Commands, and outcomes and nothing else" design_docs/design-v11.md:661 — falsified by schema_version in the RunStarted row (line 650) and by RUN-RECORDS itself. Wording-level, but this doc holds itself to exactly this standard.
Gaps
- G1. No contract rule classifies direct-return vs latched errors. The principle (pre-commitment failure → operation's own Err; post-commitment failure → latch) is derived only in sim Notes (design_docs/design-v11.md:932) and shown by example in section 10's error sums (958). A bespoke Environment author — bound by "every row" — must guess. Same underlying condition already yields different EnvironmentOperation discriminants in live (Dispatch/Checkpoint/NextEvent by timing) vs sim (pinned by code site); DET-ENV survives only because the traces differ, but forensic comparability is unpinned.
- G2. OfferRejected::Closed has no stated trigger. design_docs/design-v11.md:803,819. LIVE-SHUTDOWN closes "Engine-facing admission" — but "admission" names both the fan-in (812) and the inboxes (815). Nothing states when (or whether) Port-facing offer closes; a Port offering during shutdown gets undefined behavior. The one place two conforming Live implementations can observably diverge.
- G3. The Stop-path swallow window is entailed but unacknowledged. A live Port run(Err) published after the final checkpoint but before shutdown closes the latch is silently discarded (design_docs/design-v11.md:396,674,819) — the run exits Stopped with a forensically clean Journal despite a real Port failure. Live-only; violates no row; never acknowledged.
- G4. BOUND-SIZING is ill-defined and Event-blind. design_docs/design-v11.md:1023. "Largest batch stageable" is meaningless for variable-size Commands (one 10 GB command overflows any config), and EventAccepted's serialized event (line 653) is out of scope entirely — oversized Events kill the run at runtime with no config check possible. Misconfiguration = deterministic turn-1 Journal Fatal; undocumented.
- G5. RUN-CHECKPOINT's "Every turn observes the latch exactly once" is false on mid-turn Fatals (dispatch Err, Outcome::Fatal, overflow all end turns with zero observations — and a literal reading would call take_error after a dispatch Err, violating ENV-SERIAL). Should read "every turn reaching EffectsComplete". design_docs/design-v11.md:674,623.
- G6. DET-ENV's "every Core-owned discriminant" list omits Quiescence and Stopped-vs-Fatal (design_docs/design-v11.md:677) — both trace-forced in reality, but the list presents itself as the enumeration. Also DET-ENV carries no "same build" constraint at all, and "build" is undefined anywhere (serde_json version drift changes Journal bytes under an equal trace).
- G7. Sim requires at least one self-arming Port for any Event delivery at all — a reactive-only Port set (no arms, Events only via... nothing: only step(Some) creates candidates) Fatals Environment(NextEvent) at the first next_event. Derivable, never warned. design_docs/design-v11.md:916,918.
Ambiguities
- A1. RUN-FINALIZE's "Environment started" is undefined; a start-Err env matches both clause 1 (call shutdown — return unconstrained) and clause 3 (skip). Saved only by the explicit carve-out at design_docs/design-v11.md:595. "Started" should mean "start returned Ok".
- A2. ENV-LATCH's "observed before an operation's own commitment" governs only the racing-commitment case. Live dispatch Full (no commitment exists) + racing publication: which Err wins is answered only emergently by the mechanism text (the admission error; the latched error discarded). Also the check-then-act mechanism sketches (design_docs/design-v11.md:838,842) never show the atomicity branch (a) requires — a naive implementation of the sketch violates ENV-LATCH.
- A3. ENV-SHUTDOWN's "so each Port can observe it before processing any further queued Command" — capability vs delivery reading. try_recv yields queued Commands before the signal (design_docs/design-v11.md:817); the justify note (869) rescues it only via lifecycle(). Defensible, load-bearing, unpinned.
- A4. Sim next_event check order: latch-vs-budget is unpinned (both orders consistent with design_docs/design-v11.md:916,917) — provably unobservable (budget is fresh at entry; nothing can latch mid-next_event in sim).
- A5. Round-robin cursor: initial value stated nowhere; wrap-scan rule implied; persistence across next_event only derivable (design_docs/design-v11.md:923). Affects cross-implementation conformance, not DET-RUN.
Minor / citation hygiene
- The A4 citation for overflow-beats-Outcome is bogus ("the overflow came first" — unobservable; the state table's fixed work order does the work, not A4) — design_docs/design-v11.md:623.
- LIVE-SUPERVISION's "(A4)" for suppression is misattributed on the clean-Stop path (A4 is vacuous there; ENV-LATCH-closed is the actual license) — design_docs/design-v11.md:816.
- Latch state chain omits empty→closed (the normal clean-stop path) and reported→closed — unobservable, but the glossary/row depict a chain — design_docs/design-v11.md:94,396.
- JRN-FORMAT "bounds the encoded object" is true only of committed records (an object of exactly max+1 bytes is encoded before step-4 rejection) — design_docs/design-v11.md:455.
- Sink content fidelity (Ok results, different bytes) is a silent assumption, contradicting "an obligation absent from the table is enforced, not assumed" — design_docs/design-v11.md:1007.
- Sim start Err needn't identify the failing Port, and the Journal is empty on that path — the Error payload is the sole diagnostic.
- ENV-SHUTDOWN's signal clause holds only vacuously in sim (stop() is the only observable notice).
- set_next(== now) self-re-arm spin is bounded only by the step budget — the budget's motivating case, never named.
What survived attack
The failure-injection matrix over the state graph closes (every state × failure → exactly one outcome); shutdown called exactly-once-or-never on every path; ENV-SERIAL unviolable; Stopped⇒Quiesced; CommandsDispatched-as-final-record; the only cycle advances the index; Journal bound arithmetic is exact (the +1 sizing does precisely the work claimed), poison coverage is complete over the io::Write outcome space with no reachable re-commit, NotAnObject is sound not heuristic; sim's no-arm-below-now invariant is provable from the capability boundary; the per-Command dispatch/checkpoint latch choreography matches ENV-LATCH identically in live and sim; the live start gate has nothing fallible after commitment; nothing Environment-dependent leaks into Journal bytes (conditional on the Application obligation).
Bottom line: no structural flaw; one real spec bug (C1 — DET-ENV's premise list), a handful of genuine gaps concentrated at the seams (error-channel classification, offer closure, Stop-path swallow, BOUND-SIZING), and wording defects in exactly the sentences that overclaim ("every turn", "every Core-owned discriminant", "and nothing else"). All are one-sentence-to-one-row fixes; the mechanism designs themselves held.
