Adversarial Findings
I reviewed only the document’s semantics, using several independent passes and then challenging the candidate findings against nearby rules. I found real issues.
High Severity
1. Simulated next_event violates the commitment-point model  
References: design_docs/design-v11.md:91-92, :385, :916-917, :932-936.
next_event commits only when a candidate is consumed, and before commitment “nothing happened.” Simulation can advance now, clear an arm, advance the round-robin cursor, invoke step, and mutate Port state before any candidate exists.
Concrete trace: with a one-step budget, a Port is selected, mutates state, and returns None; budget exhaustion then returns Err. No candidate was consumed, but irreversible effects occurred before the operation’s sole commitment point.
2. RUN-CHECKPOINT contradicts legal Fatal-turn paths  
References: :70-71, :623-625, :630-639, :674.
RUN-CHECKPOINT says every turn observes the latch exactly once. But an accepted turn can go Fatal from:
- Command overflow
- Outcome::Fatal
- Failed CommandsPrepared
- Failed dispatch
- Failed CommandsDispatched
None reaches EffectsComplete, the only state performing take_error. The guarantee needs to apply only to turns reaching EffectsComplete, or Fatal turns need another explicitly ordered checkpoint.
3. Latch ordering is undefined when publication races with an operation’s own failure  
References: :385-386, :396, :838-845.
ENV-LATCH orders publication against successful commitment, but does not define precedence when the operation fails before commitment.
Concrete Live dispatch race:
1. dispatch checks an empty latch.
2. Port Error A is published.
3. Inbox admission fails with Error B.
4. No handoff commitment occurs.
It is unspecified whether A or B is returned, whether A remains pending, and therefore which Fatal cause wins. The same gap exists between the latch check and a clock-conversion failure in next_event.
4. Live Quiesced is not a sufficient witness for the contract’s definition  
References: :95-96, :388, :819, :855-858, :1016, :1021.
The contract defines Quiesced as completion of every unit of run-scoped activity. Live returns it when every supervised Port thread is joined.
A Port can spawn a native callback or helper thread and return from its supervised thread without joining that worker. Kavod would report Quiesced while run-scoped activity continues. The obligations require bounded work and lifecycle cooperation, but never require all Port-created activity to finish before run returns.
5. The authority model relies on trusted assumptions absent from the “complete” obligations table  
References: :238-241, :258-261, :301, :670, :1007-1024.
Safe values can carry aliased authority:
- An Event can contain Arc<AtomicU64> that a handler mutates.
- A staged Command can contain shared mutable state and change after emit.
- Two Ports can share Arc<Mutex<DomainState>>.
- A caller can retain a shared handle into an Environment or sink.
This breaks APP-CONTEXT, APP-FUTURE, immutable Command transfer, PORT-STATE, and potentially RUN-SERIAL. The prose explicitly says payloads must carry no hidden authority, but the obligation at line 1013 covers only handlers and State. Port ownership and alias restrictions are not assigned to anyone.
6. JRN-SINK is an unenforceable condition classified as enforced  
References: :51-55, :423-426, :455-459, :493-495, :1007-1024.
JRN-SINK requires a fresh sink or one positioned after a newline. W: Write provides no way to verify existing bytes or position.
A writer containing partial can be passed to Journal::new; the first successful commit then creates partial{...}\n, violating JRN-FORMAT. Aliased writers can also inject bytes between records. No sink-owner obligation covers freshness, positioning, or exclusive access.
7. DET-ENV is false without additional common-input premises  
References: :99-101, :676-677.
DET-RUN fixes the build, Application, initial State, configuration, and trace. DET-ENV requires only equal traces.
Two runs can have equal Environment and sink results but different Applications, initial States, or max_commands_per_turn, producing different State transitions, Commands, and Journal bytes. DET-ENV must inherit the non-Environment premises from DET-RUN.
Trace equality is also underdefined: Events need only Serialize, lossy serialization is allowed, and cross-Environment operation result types may differ.
8. Simulated on_command(Err) propagation is not actually normative  
References: :396, :914, :923-935.
The intended behavior is:
- Invocation commits handoff.
- on_command(Err) is placed in the latch.
- The current dispatch returns Ok.
- The checkpoint observes the Error.
But SIM-DISPATCH says only that invocation commits handoff. Latching and returning Ok appear in Mechanism/Derive prose. ENV-LATCH governs Errors that are published, but never requires this Error to be published.
Under the document’s binding-form rules, an implementation could discard the Error after handoff and complete the turn normally.
Specification-Structure Contradictions
 9. The Obligations table is outside the document’s own binding grammar  
References: :13-24, :51-55, :1007-1024.
Section 0 recognizes exactly three binding forms:
- API blocks
- Guarantee rows with IDs
- Specifically enumerated binding tables
The Obligations table is not one of the enumerated binding tables, and most of its rows have no IDs. Section 12 nevertheless says those rows are the complete trusted boundary. Either the obligations do not bind, or the “three forms bind” rule is incomplete.
10. Fatal finalization is missing from tables declared exhaustive  
References: :21-24, :618-643, :675.
The Run’s state and edge tables are declared exhaustive: unlisted work does not happen. Fatal paths classify causes, but there is no Fatal/finalization state or edge containing shutdown, quiescence resolution, and Fatal exit construction.
RUN-FINALIZE separately mandates that work, producing a conflict between the exhaustive graph and the guarantee. Finalization should be represented in the graph or explicitly excluded from table exhaustiveness.
11. RUN-GRAMMAR overstates compile-time enforcement  
References: :671, :726-738, :1034-1035.
RUN-GRAMMAR says the graph is enforced at compile time. The proof boundary later admits that tokens are affine: dropping one and omitting required progress compiles, with omissions detected only by golden tests.
The type state does enforce record ordering and prevents completion without the required witnesses. It does not prove that every token drop corresponds to a genuine Fatal condition or that all mandatory outgoing transitions are taken. The guarantee should state the narrower property it actually establishes.
Medium Severity
12. Simulated event timestamps are not tied to virtual now  
References: :397, :896-905, :913, :916.
Simulation advances now to the selected arm time before calling step, but no guarantee requires a step(Some(event)) result to be paired with that now.
A simulated Environment could advance now to 100 but return the Event stamped 0, provided stamps remain nondecreasing. That satisfies ENV-TIME while making handler logical time disagree with SimCtx::now.
13. The commitment definition is too absolute for the document’s layered effects  
References: :91-92, :384, :457-458.
“Before the commitment point, nothing happened” conflicts with acknowledged subordinate effects:
- start may perform effects that stand even when activation never succeeds.
- Journal writes may leave an uncertain physical suffix before flush commits the record.
- Simulated selection mutates simulation state before candidate consumption.
The design appears to mean “the operation’s contractual primary effect has not happened,” but that narrower scope is not defined. Without effect scopes, A3 cannot consistently describe nested operations.
14. Live start can return success after all activity has already ended  
References: :384, :816, :818, :835-836.
After the start gate is published, a Port may immediately fail and its supervised thread may terminate before start returns. start still returns Ok, while the commitment table says success means run-scoped activity “is live.”
The intended behavior is probably “activation succeeded irrevocably; any subsequent failure is runtime failure.” That is different from guaranteeing activity remains live at return.
Lower-Severity Internal Errors
15. A Fatal Journal does not necessarily physically end at its last committed record  
References: :457-458, :493-495, :659-660.
A failed write or flush can leave a partial or complete uncommitted line after the committed prefix. Therefore “the Journal simply ends at its last committed record” is true only of the logical committed sequence, not sink bytes.
16. A4 cannot justify overflow beating an Application Error  
References: :87-89, :114, :623.
A4 orders the first Error observed. CommandBoundExceeded is a Core condition, not an Error. The state table clearly specifies that overflow wins, so behavior is settled, but the claim that this follows from A4 is incorrect. A4 must cover the first Fatal-producing Error or Core condition.
Areas That Held Up
I found no semantic defect in:
- Index exhaustion ordering
- Candidate consumption versus acceptance
- Dispatch-prefix accounting
- Stop-path reuse of Incomplete
- Journal encode-before-write and poisoning rules
- Simulated equal-time round-robin selection
- The distinction between normal Stop and finite-source exhaustion
The design has a strong core, but the commitment model, trust boundary, latch race semantics, and exhaustive graph claims need tightening before it is fully robust.
