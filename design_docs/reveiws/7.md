dversarial Review of design_docs/design-v11.md
Document Evaluated: design_docs/design-v11.md (Kavod Core Design v11)  
Scope: Core semantics, invariants, type system, error propagation, determinism, and execution contracts.
Executive Summary
The overall typestate architecture (RUN-GRAMMAR), bounded allocation discipline, Journal write-and-poison state machine (JRN-*), and trace-based determinism abstraction (DET-ENV/DET-RUN) are exceptionally well-grounded.
However, an adversarial analysis across execution traces, multi-threaded concurrency models, and simulation scheduling identified two critical semantic contradictions in error propagation/latching, along with several type system, lifetime, and API-level issues that break core invariants if implemented as specified.
1. Critical Semantic Issues & Protocol Breaks
Finding 1: The Sim Dispatch Latch-Poisoning & Batch-Size Divergence
- Locations: Line 624 (Prepared), Line 815 (LIVE-DISPATCH), Line 914 (SIM-DISPATCH), Lines 925–928 (Sim Mechanism), Lines 932–935 (Sim Notes), Line 677 (DET-ENV).
- The Contradiction:
In the Simulated Environment, SIM-DISPATCH (line 914) states that synchronous invocation of SimPort::on_command is the handoff commitment. Lines 925–928 and 932–935 state:
"invoke on_command — an Err from it lands in the latch and the dispatch still returns Ok, because invocation already committed."
"a pending latch Error first (ENV-LATCH)"
When a turn stages a batch of $M \ge 2$ commands $[c_0, c_1]$:
1. Engine dispatches $c_0$. PortA::on_command(c_0) returns Err(E_0).
2. SimEnvironment::dispatch latches E_0 and returns Ok(()) to the Engine.
3. Engine assumes $c_0$ was handed off cleanly and advances to $c_1$.
4. For $c_1$, SimEnvironment::dispatch checks the latch per ENV-LATCH, observes pending(E_0), and returns Err(E_0) before $c_1$ is ever routed or invoked.
5. Engine receives Err at $k = 1$ and assigns:
FatalCause::Environment(EnvironmentFatal { error: E_0, operation: Dispatch { position: 1 } }).
6. Per line 624, the Engine certifies that prefix $[0, 1)$ ($c_0$) was cleanly handed off and that $c_1$ failed handoff.
- Consequences:
1. False Forensic Attribution: $c_0$ was the command that failed, but the exit diagnostic certifies $c_0$ succeeded and attributes the failure to $c_1$ (which was never executed).
2. Batch-Size Invariance Violation:
- If the batch is [c_0] (length 1): dispatch(c_0) returns Ok(()). The Engine commits CommandsDispatched to the Journal (claiming all commands were handed off!), and fails at take_error() in EffectsComplete, reporting EnvironmentOperation::Checkpoint.
- If the batch is [c_0, c_1] (length 2): CommandsDispatched is never committed, and the failure surfaces as Dispatch { position: 1 }.
- The exact same failure on $c_0$ produces divergent Journal records and divergent FatalCause variants based solely on batch length.
3. Violation of DET-ENV: In Live execution, an asynchronous port crash surfaces at Checkpoint or NextEvent. In Sim execution (batch $> 1$), it surfaces at Dispatch { position: 1 }. Equivalent port domain failures produce divergent Core-owned exit discriminants.
- Remediation: In synchronous simulation, eliminate latching inside dispatch. If SimPort::on_command returns Err(E), SimEnvironment::dispatch must return Err(mapped_error) synchronously and immediately at position $k$. Mutations made up to that point stand per A3/A4.
Finding 2: Silent Swallow of Live Port Crashes During Clean Stop (StopPending Race)
- Locations: Line 396 (ENV-LATCH), Line 625 (EffectsComplete), Line 627 (StopPending), Line 816 (LIVE-SUPERVISION), Line 819 (LIVE-SHUTDOWN).
- The Vulnerability:
1. Application handler returns Outcome::Stop.
2. Engine enters EffectsComplete and calls take_error() (RUN-CHECKPOINT). The latch is empty; checkpoint witness is minted.
3. Engine commits StopRequested record and transitions to StopPending.
4. The Race Window: Before or during env.shutdown(), a Live Port worker thread crashes while in Lifecycle::Running (run() returns Err or exits prematurely).
5. LIVE-SUPERVISION catches the crash and publishes pending(PortCrash) to the latch.
6. Engine calls env.shutdown().
7. Per ENV-LATCH (line 396) and LIVE-SHUTDOWN (line 819): shutdown() closes the latch and unconditionally discards the pending error.
8. Because the thread exited, shutdown() successfully joins all threads before the deadline and returns Quiescence::Quiesced.
9. Engine mints the quiescence witness, commits TurnCompleted(Stop), and exits cleanly with EngineExit::Stopped { state }.
- Consequences: A fatal crash on a live port occurring during active Running execution is completely erased, falsely reporting a clean and successful application termination (violating Axiom A4).
- Remediation: In StopPending (or at the entry of shutdown), the Environment must check the latch. If a pending error was published during Running, it must transition to FatalCause::Environment(EnvironmentFatal { error, operation: Checkpoint }) instead of completing a clean Stopped exit.
2. Type System, Macro, and API Inconsistencies
Finding 3: Missing Send + 'static Bounds on LivePort / LiveCtx
- Locations: Section 8 (API block, line 785) & LIVE-THREADS (line 811).
- Defect: 
pub trait LivePort<C: PortContract>: Send + 'static {
    type Error: Send + 'static;
    fn run(self, ctx: LiveCtx<C>) -> Result<(), Self::Error>;
}
PortContract only bounds associated types with Serialize (to allow !Send simulated ports).
However, LiveCtx<C> passes C::Command and C::Event across thread channels between the Engine and Port threads.
- Impact: Under #![forbid(unsafe_code)], multi-threaded channels cannot compile without Send + 'static bounds on C::Event and C::Command.
- Remediation: Add where C::Event: Send + 'static, C::Command: Send + 'static to LivePort.
Finding 4: Pervasive Omission of Standard Derives (Debug, PartialEq, Eq, Error)
- Locations: API blocks across Sections 3, 5, 6, 7, 8, 9.
- Defect: Section 0 states listed derives in API blocks are exact. Multiple public types omit essential derives:
1. EngineExit, FatalCause, EnvironmentFatal, EnvironmentOperation, JournalFatal, CoreError: Lack PartialEq, Eq, Debug. Guarantees DET-RUN and DET-ENV explicitly mandate comparing exit discriminants for equality across test runs.
2. Outcome<E>, Quiescence, PortInput<Cmd>, OfferRejected, Lifecycle, SimCtxError: List zero derives (need Debug, Clone, Copy, PartialEq, Eq).
3. JournalBuildError, JournalError, SinkOperation: Lack std::error::Error, Display, and Debug.
4. EventIndex and Timestamp: Omit Debug and Hash.
Finding 5: ports! Macro Hygiene and Feature Limitations
- Locations: Section 4 (lines 287–295, 310–325).
- Defect:
1. The macro expansion hardcodes ::kavod::PortContract instead of $crate::PortContract, breaking internal crate use and aliased imports.
2. The macro expansion generates strictly #[derive(::serde::Serialize)] and rejects pass-through outer attributes $(#[$meta:meta])*. Application authors cannot add #[derive(Debug, Clone)] to their generated Event/Command enums without manually expanding the macro.
Finding 6: Missing Type Definitions & Timestamp Helpers in API Blocks
- Locations: Section 3 (lines 183–191, 221–232).
- Defect:
1. Section 3 includes impl<'a, C> Context<'a, C> but omits the pub struct Context<'a, C> { ... } definition from the normative API block.
2. Timestamp provides checked_add(Duration) but provides no subtraction or elapsed duration helper (checked_duration_since or saturating_duration_since), forcing ports to unwrap raw nanoseconds and reconstruct Duration values manually.
Finding 7: Section 10 Open Item Vulnerability: Slot Ordering vs. Determinism
- Locations: Section 10 (Wiring, line 966) & SIM-SELECT (line 916).
- Defect: Section 10 lists as an open decision: "What fixes the Slot order: registration order, or the Slot sum's declaration order."
- Impact: SIM-SELECT tie-breaking, SIM-START, and LIVE-SHUTDOWN join ordering all depend on "frozen Slot order". If Slot order is determined by registration order in a dynamic builder, non-deterministic builder registration order would alter scheduling tie-breaks, violating DET-RUN. Slot order must be strictly anchored to declaration order in ports!.
3. Verified Robust Subsystems (No Issues Found)
The following subsystems were subjected to adversarial testing and verified to be structurally sound:
1. Journal Buffer Allocation & Sizing Protocol (JRN-FORMAT / JRN-ENCODE): Sizing the buffer to max_record_bytes + 1 mathematically guarantees that all objects $\le \text{max\_record\_bytes}$ succeed with newline appending, while any object $> \text{max\_record\_bytes}$ fails cleanly as BoundExceeded without touching the sink.
2. JSON Object Root Validation: Inspecting leading { and trailing } on compact serde_json output is an optimal $O(1)$ guard against non-object roots.
3. Sink Write Loop & Poisoning (JRN-POISON / JRN-COMMIT): Retry loop strictly bounds iterations by record length, converts Ok(0) to WriteZero, rejects Interrupted immediately, and prevents double-commit panics.
4. Token Typestate Graph (RUN-GRAMMAR): Recorder<W, S> using PhantomData<fn() -> S> ensures auto-trait independence (Send/Sync), while affine witness consumption prevents skipped checkpoints or illegal transitions at compile time.
5. Simulation Step Budget (SIM-STEPS / BOUND-LOOPS): Resetting the step budget on every next_event acquisition prevents step(None) infinite loops while avoiding artificial run-level budget exhaustion.
6. Round-Robin Cursor (SIM-SELECT): Persistent cursor ensures starvation-free round-robin tie-breaking across equal timestamps and properly advances even on step(None) transitions.
