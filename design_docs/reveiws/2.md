Verdict

The core semantics are strong. Every attempt to break the run graph, the latch linearization, first-failure-wins under races, the Journal's byte-bound arithmetic, poison paths, RUN-FINALIZE's branch coverage, the token corollaries, and the finite-source pattern end-to-end failed — the design's machinery holds. What the attack did find: five genuine spec gaps where two conforming implementers could diverge, and a cluster of places where the doc violates its own meta-rules — which matters more than usual here, because section 0's epistemology ("a rule in none of the three forms does not exist") is load-bearing.

Tier 1 — Genuine gaps (two conforming readers diverge)

1. The Sim never says what Timestamp next_event returns. SIM-SELECT says "advances now, clears the arm, and calls step" — but never says advances to what, and never says the candidate is stamped with now. There is no SIM-TIME row realizing ENV-TIME (Live has LIVE-TIME), despite section 9's own preamble: "every guarantee below realizes a named contract row." A sim that stamps with pre-advance now violates no written row yet produces different Journal logical_time bytes. This is the most concrete hole found. Fix: one row — now advances to the selected arm's time; the candidate is stamped with now; realizes ENV-TIME.

2. EventAccepted's index value is derivable two ways — an off-by-one lives in the text. Enforcement says transitions build "payload from the token's own index"; RUN-INDEX says the index advances "exactly when EventAccepted commits." Payloads are built before commit, so the literal reading puts index: 0 on the first External Event — colliding with RunStarted and contradicting EventIndex's "External Events from 1." Nothing in RUN-RECORDS or the records table pins the value. Fix: state that a record's index is its turn's index, and that accept_event's derived index is the payload's.

3. No binding rule empties the batch buffer between turns. APP-OVERFLOW resets only the marker ("A fresh handler invocation starts with the marker clear"); the mechanism says the buffer is "reused every turn"; the state table discards the batch only on Fatal rows. The glossary's "Batch — the ordered Commands one turn stages" is a definition, and by your own rule definitions create no obligation. An implementation that never clears — turn 2's CommandsPrepared records turn 1's Commands, dispatching them twice — violates no ID. Found independently by two agents. Fix: extend APP-OVERFLOW to "starts with the buffer empty and the marker clear."

4. PORT-ROUTING's Error-mapping clause has no referent in Live. "Each arm mapping its Port Error into the Environment Error sum" is exactly Sim's shape (on_command's Err is in scope at the arm). In Live, dispatch arms do inbox admission — the only errors in scope are Kavod-owned queue errors; the Port's Error surfaces asynchronously through LIVE-SUPERVISION, outside any match arm. A live wiring author cannot literally discharge the obligation (nor the trusted-obligation clause "each arm naming its... mapping"). Fix: split routing (the fan-out match) from per-Slot Error mapping (into the Env sum), letting each Environment place the mapping at its own site — and resolve it when Wiring closes.

5. The Trace definition doesn't say Ok payloads are included — and DET-ENV needs them. DET-ENV demands "CoreError including payloads," and TimeRegression { previous, offered } carries the stamp of a candidate that was never accepted — so offered is trace-pinned only if "every Environment operation result" means full returned values. The parenthetical ("Error values... erased") discusses only Err content, inviting a discriminants-only reading under which DET-ENV is unsatisfiable. One phrase fixes it.

Tier 2 — The doc breaks its own taxonomy

6. JRN-SINK's "A sink is fresh for one run or positioned immediately after a newline" is an unenforceable caller obligation missing from the Obligations table. Kavod cannot observe a Write's position; section 12 says "an obligation absent from it is enforced, not assumed" — false at this row. The bespoke-Environment carve-out doesn't cover it (a sink is a supplied value, not a contract implementation). Found independently by two agents. Fix: add an Obligations row.

7. Section 0's definition of "enforced" excludes its own third tier. "Kavod makes violation impossible or panics" — yet the enforcement order ends "Tests cover the rest," and the doc itself concedes RUN-RECORDS is "pinned by byte-exact golden tests" and the affinity gap is "caught by golden-Journal tests, never the compiler." Worse, DET-RUN/DET-ENV sit in the enforced class while section 3's own Notes concede they rest on the Application author's trusted obligation. A handler reading SystemTime violates DET-RUN with no panic and no test that can catch it on a single run. Fix: widen the definition (impossible / panics / test-pinned) and state the DET rows' conditionality in the rows.

8. A4 doesn't ground Error-discard on the clean Stop path. A4's discard clause is conditioned on a first Error existing ("Everything after is best-effort cleanup"). But LIVE-SHUTDOWN/SIM-SHUTDOWN/ENV-LATCH-closed all cite A4 to discard stop() Errors on runs that exit Stopped with no Error ever observed. The behavior is clearly intended (and separately acknowledged in RUN-CHECKPOINT), but "Everything in this document is a consequence of eight axioms" fails here. Related mis-citations in the same class: SIM-START cites A3 where the commitment table cites A4's cleanup rule for the identical proposition; TurnOpen's overflow-beats-Outcome cites A4, but overflow is a Core condition, not an Error, and A4 governs Errors. Fix: extend A4 ("after the first Error, or after shutdown begins") and normalize the citations.

9. #![forbid(unsafe_code)] and "relies on unwinding nowhere in shipped code" are prose-only rules. Neither is an API block, guarantee row, or binding-table row; by your own deletion test both are rules in the wrong clothes (the Obligations row covers only the final binary's abort profile). Fix: give them IDs in Laws.

10. The bounds registry — labeled navigation — ends with two unowned rules. "Slot registration at construction fixes the Port set, the thread count, and the Slot order: static, not configured" and "Every configured capacity uses a nonzero type" have no ID and no owner section (the nonzero rule reappears only in the OPEN Wiring constraints list). A future LiveConfig taking a plain usize would violate nothing binding.

11. Load-bearing vocabulary missing from the Glossary, which claims definitions "appear only here": "External Event" (used in EventIndex docs, APP-FUTURE, RUN-INDEX, and the binding records table), "run-scoped activity" (the term Quiesced's truth condition pivots on — undefined exactly where bespoke Environments are trusted to witness it), "flat" in "flat JSON object" (false under its ordinary reading — event payloads are nested objects), and arguably "publish" (latch entry vs. gate publication).

Tier 3 — Wording contradictions, intent recoverable

12. RUN-CHECKPOINT: "Every turn observes the latch exactly once" is false by ENV-LATCH's own definition of observation — a 3-dispatch turn observes four times (each dispatch is latch-observing per the linearization), a turn dying at TurnOpen observes zero times, and the row itself concedes the broader sense ("the next observing operation"). Fix: "takes the latch snapshot (take_error) exactly once" scoped to completing turns.

13. "Records carry indices, times, Events, Commands, and outcomes and nothing else (RUN-RECORDS)" — false: record_kind and schema_version are none of those. The DET-ENV conclusion survives (both are constants), but the derive is wrong as written and a conformance author enumerating from it rejects every record.

14. RUN-GRAMMAR: "a wrong index... fails to compile" overclaims. Caller-supplied indices are unrepresentable, but index correctness is runtime arithmetic — your own honesty inventory lists the start-index check as a residual assert. The row's absolutism contradicts the section's own boundary statement.

15. ENV-LATCH's state chain omits two reachable transitions. As written, closed is reachable only from pending; but shutdown closes unconditionally, so empty→closed (clean run) and reported→closed (post-Fatal finalization) occur and are undefined by the machine. Behavior is unambiguous downstream ("After reported or closed…"); the notation is incomplete.

Tier 4 — Small stuff

- The non-normative sketch misdraws the only cycle: EventAccepted visually rises out of EffectsComplete, and BetweenTurns has no outgoing edge.
- EnvironmentOperation::NextEvent lacks the "possibly an unrelated already-latched Error" caveat that Dispatch carries, though LIVE-SELECT makes it equally true there.
- Wiring's sim Error sum lists time-domain exhaustion, which no section-9 rule can produce (set_next rejects only TimeBeforeNow; no sim arithmetic exists) — vestigial or §9 owes a rule; resolve at Wiring close.
- SIM-SHUTDOWN claims to realize ENV-SHUTDOWN but never says what the shutdown signal is sim-side (presumably the stop() call) — and the finite-source pattern's "awaits the shutdown signal" has no sim meaning as written.
- ENV-SERIAL says nothing about the call pattern after take_error returns Some; a bespoke caller may legally continue against a permanently reported latch (error-blind, possibly blocking forever). Kavod's Run never does this; one sentence would close it for bespoke implementors.
- Naming drift: transition-table Regression vs CoreError::TimeRegression; ENV-BOUNDS cites "(Laws registry)" for the thing named "bounds registry"; registry says "per acquisition" where SIM-STEPS says "per next_event invocation"; ports! input names Trading, an item the expansion never creates; DET-ENV's equality list is asymmetric (payload equality demanded for CoreError but not Dispatch { position }, and exit quiescence is unlisted); binding-table rows have no IDs, so the "Cite IDs, never section numbers" rule can't be followed for them — the doc itself resorts to "(commitment table)."

What held under attack

For calibration, the attacks that failed: every first-failure-wins race interleaving (the observed-first, not wall-clock-first, wording resolves all of them); the sim mid-batch latched-error-at-unrelated-position scenario (fully coherent, prefix semantics intact); Journal boundary arithmetic at max−1/max/max+1/max+2 (every case uniquely determined, step 4 is live precisely at max+1); the poisoned-commit panic being unreachable from the Run; all RUN-FINALIZE quiescence branches including the nasty ones (TurnCompleted(Stop) commit failing after a successful shutdown); SIM-START's pre-Port-start commitment placement (sanctioned by the table's "binds outcomes, not instants"); the arm-regression attack on sim time; and the finite-source pattern in both environments including Fatal-during-Stop-turn. Appendix A's ID inventory is exactly accurate.

Nothing here breaks the architecture — every Tier 1–3 item is fixable with a sentence, a row, or a moved clause. The pattern across findings: the run's machinery is watertight, but the Sim section and the doc's self-referential taxonomy got less adversarial attention than the graph did. Happy to draft the repair edits if you want them.
