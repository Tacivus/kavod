Adversarial review: design-v11.md
Verdict: not solid. No topology-breaking contradictions (the graph has no dead ends, finalization never double-calls shutdown as written, the latch algebra closes), but there are ~15 major findings — mostly places where a normative claim is underpinned by prose, an axiom is cited past its scope, or a guarantee row overclaims its mechanism — plus a shelf of minors. Ordered by severity within tiers.
Tier 1 — Semantics gaps: a conforming implementer could build the wrong thing
1. LivePort's API block cannot realize LIVE-THREADS — missing Send + 'static on the payload types.
L279–282: PortContract bounds only Serialize. L785–788: LivePort<C: PortContract>: Send + 'static bounds the Port and type Error: Send + 'static — but nothing bounds C::Event: Send + 'static (crosses the fan-in channel at offer, L797) or C::Command: Send + 'static (crosses the inbox at recv, L792). L811 claims "Everything crossing a Port-thread boundary — values moved in, Commands in, offered Events out, Port Errors out — is Send + 'static"; the stated bounds deliver two of the four. An Rc-containing payload with a hand-written (trusted, L1020) Serialize satisfies every written bound and cannot be spawned. The asymmetry (they bounded Error, forgot the payloads) shows intent; and L971 lists "Send + 'static boundaries" among "Constraints already fixed" — the doc believes this is settled. Fix: add C::Event: Send + 'static, C::Command: Send + 'static to LivePort (keep them off PortContract — sim needs none).
2. SIM-SELECT never states the returned candidate's Timestamp.
next_event must return (Event, Timestamp) (L361) and ENV-TIME requires stamping every next_event (L397). L916 says "advances now, clears the arm, and calls step. Only step(Some) creates the returned candidate" — the Event is named, the stamp never is, and the sim Mechanism (L923–928) contains no stamp sentence. Live pins it explicitly (L839–841: "return it with that stamp"). "Arm time (new now)" vs "now at entry" both satisfy nondecrease and yield different EventAccepted.logical_time bytes — a wire-visible ambiguity. Fix: "the returned candidate is paired with the advanced now."
3. The dispatch-prefix fact is not in the Journal — the "Journal is the evidence after death" story has a hole.
L659–661: "CommandsPrepared plus the typed Dispatch { position } identify the exact handed-off prefix." But position lives only in EngineExit (L564) — process-local. The panic story (L125–127: "After a panic the evidence is the Journal's committed records") and the Live Incomplete note (L862–863: "The evidence is the Journal's committed records") both lean on the Journal alone. Sequence: CommandsPrepared commits (5 commands) → dispatch fails at k=2 → finalization's shutdown panics → abort, no exit → the Journal cannot distinguish 0/1/2 handed-off commands. The uncertain-prefix set is exactly what the business-key obligation (L1019) exists to resolve. Fix: commit the position — e.g. a position field committed on the dispatch-failure edge — or explicitly scope the forensic claim.
4. ENV-SHUTDOWN's observability clause is only interpretable by forward reference to Live prose.
L398: "raises the shutdown signal so each Port can observe it before processing any further queued Command." L817 (LIVE-LIFECYCLE): "try_recv yields queued Commands first and the signal after them, which is the draining path." A try_recv-looping Port processes all 50 queued Commands before seeing the signal. The justify (L869–871) works only under a capability reading ("an immediate observation channel exists" — lifecycle()), never stated in the contract. Two independent agents landed here. This violates the doc's own rule: "a fact any conforming Environment implementor would need lives in the contract" (L46–47) — a bespoke implementer reading only section 5 can build a drain-only design that is non-conforming under the intended reading. Fix: state the capability invariant in ENV-SHUTDOWN itself ("from that instant, each Port has a means to observe it immediately, regardless of queued Commands; a channel's ordering of the signal against already-queued Commands is implementation API").
5. RUN-FINALIZE's "consumed by the Stop path" must explicitly cover the TurnCompleted(Stop)-edge Journal failure.
I walked every Fatal path against L675's three cases; exactly one applies each — except by wording: a Journal failure committing TurnCompleted(Stop) happens after StopPending minted the quiescence witness, i.e. the Environment was consumed by StopPending's shutdown. Whether that edge failure is "the Stop path" is undefined; a misreading implementer re-calls shutdown, violating ENV-SERIAL's "at most once" (L394). Fix: "consumed — exactly when StopPending ran → reuse that call's result."
6. RUN-INDEX's boundary check is not pinned to the arithmetic.
L626/L673: "at the u64 boundary → Core(IndexExhausted)". Start turn is index 0, first external event index 1, so max turns = u64::MAX + 1 and the check is index == u64::MAX — but "the boundary" also admits index + 1 == u64::MAX (losing one turn). The doc's own bar is exact arithmetic spelled out (checked_add(1), L475); this one is not. Also: on TimeRegression the consumed candidate's event value appears only in the trace (via the next_event result), not in the exit (L575 carries only timestamps) — worth one sentence. Fix: "when the token's index equals u64::MAX"; note the candidate is trace-only.
7. accept_event must pin "regression check precedes commit".
L642 says nondecrease is "checked inside the transition" but never says before the commit. Commit-then-check compiles the mechanism and produces a Journal evidencing acceptance (EventAccepted: "Acceptance of one External Event", L653) of an event the exit rejects via TimeRegression — and divergent bytes across implementations, breaking DET-ENV. Fix: "the nondecrease check precedes the commit; a violation commits nothing."
Tier 2 — The determinism story (all fixable with scoping language)
8. "Sink operation result" granularity is undefined, and DET-RUN's byte-equality hinges on it.
Trace (L99–101): "every sink operation result — Error values (not their presence or position) erased". If "operation" = one write/flush call with its Ok(n) count (counts are not Error values, so not erased), the trace determines bytes and DET-RUN holds. If "operation" = one commit, then a short-write-then-fail vs fail-immediately pair share a trace but leave different sink bytes, and DET-RUN's "Journal bytes" (L676) is falsified. The claim survives only under the per-call reading, which appears nowhere. Fix: "a sink operation is one write or flush call on the Sink; its result is the Ok count or the failure's presence." Also scope the byte claim: "Journal bytes through the last committed record" (the uncertain suffix is outside DET-RUN's scope by JRN-COMMIT).
9. DET-ENV needs an explicit compatibility condition — the two shipped Environments structurally diverge on error paths.
Equal traces require equal error presence and position. But for the same Port-level failure: live's dispatch returns Err at position k (full inbox, L842–845); sim's dispatch returns Ok and the failure surfaces one operation later at the checkpoint (Some, L926–928). Different presence at the same position → no equal traces exist for latch-mediated dispatch failures → DET-ENV is vacuous on exactly the paths the conformance suite (L1039–1041) is meant to compare. Similarly, finite input: live blocks forever (L813), sim exits SIM-COMPLETION (L918) — "equal exits" compares an exit to a non-exit. The row is never false (material implication), but its usable domain — error-free runs plus start/next_event/checkpoint errors — is stated nowhere. Note the verification convention (L1028–1030) already quietly scopes itself to "every Core-owned discriminant", not bytes. Fix: add a trace-compatibility definition and condition the row on it.
10. The Trace is circular as a replay input.
"the accepted (Event, Timestamp) sequence … plus the run's Quiescence" (L99–101): acceptance requires a successful commit and Quiescence is shutdown's result — both run outputs. As a post-hoc description (conditional determinism, which is how L764–765 uses it) it's coherent; as the replay input the sim Notes promise (L942–945) it's undefined: a replayer presents candidates, cannot pre-know acceptance, and gets no rule for matching Quiescence. Fix: split Recorded Trace (output, basis of DET-RUN) from Replay Trace (input: candidate sequence + scripted operation results; no Quiescence).
11. Byte-equal sim replay has three unstated preconditions.
To reproduce a recorded live trace: SimConfig origin must equal the recorded RunStarted.logical_time (L913 vs L652); the replaying SimPort must arm each recorded timestamp in order and return Some at every arm (a None consumes budget and manufactures trace divergence); step budget ≥ recorded event count (L917). All "user wiring" by design, but nothing lists them — every replay author re-derives silently. Fix: one paragraph or a shipped reference replay adapter.
Tier 3 — Guarantee rows vs their mechanisms / axioms vs their citations
12. RUN-GRAMMAR's "fails to compile" list is partly contradicted by its own enforcement section.
L671 claims compile-failure for six phenomena; L728–734 then disclaim omission ("caught by golden-Journal tests, never the compiler") and payload content ("assertion and test territory"). Order violations, wrong index, wrong outcome, skipped checkpoint, premature TurnCompleted(Stop) are genuinely type-level (phases, token-derived index, transition-pinned outcome, affine witnesses — verified sound, including the PhantomData<fn() -> S> Send/Sync claim). But "a record whose kind disagrees with its payload" rests on constructor discipline (record_kind: Self::KIND, L714–716): a module-internal mismatch compiles. The row also omits the affinity caveat its own section states. Fix: re-scope the row ("unrepresentable at the module boundary; omission caught by golden-Journal tests") or make the tag's type carry the kind (ZST field) so divergence is unconstructible even in-module.
13. Handler State mutation has no commitment point — the most consequential semantic fact in the design is only inferable.
A3 (L113) binds "every effectful operation", yet the commitment table covers five Environment ops only. On Fatal, the turn's batch is discarded but State mutations stand (returned in EngineExit::Fatal, L540–545) — the sim Notes state exactly this for Port mutations (L934–935) and SIM-START cites it (L913), but nothing anywhere states it for Application State. Fix: one line in the TurnOpen row or glossary: "A handler's State mutations have no commitment point and are never rolled back; they stand on every exit."
14. A1 as worded ("one representation") is false of the design; A4 is cited past its scope.
- A1: the index lives in the token, every record, and Context::index(); the ownership map lists time under both Environment ("time stamping", L159) and Run ("the token (index and time)", L161). The design consistently practices "one owner, one authoritative store, derived views" — the axiom should say that.
- A4 says "the first Error"; the overflow rule (L623) cites it to arbitrate between a Core condition and a returned Fatal payload, with the parenthetical "(A4: the overflow came first)" asserting a temporal order the mechanism makes unverifiable (handler computed Fatal(e) possibly before the overflowing emit; the check runs after return). What the row actually needs is a priority rule (Core beats Outcome), which its own normative text already provides — the citation is the defect. Similarly RUN-FINALIZE's "fix the first-observed cause (A4)" where causes include CoreErrors. Fix: widen A4 to "first Error or Core condition", or drop the temporal fiction.
- SIM-START (L913) cites (A3) for the no-rollback clause the doc elsewhere attributes to A4's cleanup rule (L120–121, L384).
15. BOUND-SIZING is under-scoped and JRN-SINK's sink-freshness rule falls outside the "complete" Obligations boundary.
- L1023 sizes max_record_bytes against "the largest batch" — but EventAccepted carries an arbitrary-size user Event with the same BoundExceeded exposure, and deployment cannot size against payloads it doesn't control. The obligation should cover the largest record, events included.
- L459: "A sink is fresh for one run or positioned immediately after a newline" — unenforceable by Kavod, and absent from the Obligations table, which claims "an obligation absent from it is enforced, not assumed" (L1009). Genuine hole in the complete-boundary claim.
Tier 4 — Meta-rule violations (the doc breaks its own section 0)
16. The Obligations table is a fourth normative form section 0 never sanctions. L19–20: "A rule in none of the three forms does not exist" — yet 10 of 12 Obligations rows have no IDs, making them uncitable ("Cite IDs", L43) and formless. Fix: name it the fourth form (trusted rows) and ID every row.
17. L149–151 fails the deletion test. "Slot registration at construction fixes the Port set, the thread count, and the Slot order… Every configured capacity uses a nonzero type" — two global rules in Laws prose, no ID, no table. The only restatement lives in the open section (L971–972). Also: the sim "time domain" registry entry (L147) has no owner-section rule, and section 10 plans a sim "time-domain exhaustion" Error variant (L960) that appears structurally impossible (sim never does time arithmetic — now only advances to arm values). One of the three places is wrong.
18. "run-scoped activity" is load-bearing and undefined. Used by the Quiescence definition (L95), start/shutdown commitment rows (L384, L388), ENV-START (L395), LIVE-SHUTDOWN (L819) — never defined. Both shipped impls pin it (threads joined / structural); a bespoke Environment implementer cannot recover its scope (does it include handed-off Command residue? L398 suggests not). This is the glossary's job. Related glossary gaps: witness (two senses, L380 vs L719), lifecycle, External Event (used normatively at L179/L241/L653), handoff, frozen, externally consequential (scopes the L1019 obligation), "acquisition" (dead vocabulary in L147).
Tier 5 — Minors (one line each)
- ENV-LATCH (L396): "observed" is the wrong trigger (an implementation that never looks is vacuously conforming) — make it "a publication linearized before the operation's commitment"; and "first Error" presupposes a publication–publication order never granted.
- ENV-START: "lifecycle ended" is undefined and untestable for bespoke environments; reword in contract vocabulary ("will receive no further call").
- ENV-SHUTDOWN: "rejects new Commands" has no referent — consuming shutdown + one serial caller makes it dead wording (fails the deletion test).
- "receiver style are free" (L16–17) conflicts with load-bearing consumption (shutdown(self), run(self)) — scope the freedom.
- Compile-fail suite (L1034–1035): the grammar types are module-private, so external ui tests can only prove non-export, not per-violation rejection.
- ports! expansion uses ::kavod paths (L312) — breaks under dependency renaming; $crate is the robust form (the doc gets ::serde right, making this conspicuous).
- Within-section forward citations (L384→L395, L625→L674, etc.) violate a literal "Citations point backward"; scope the rule to cross-section. Section-number citations (L3, L131) violate "Never section numbers"; the enforcement-order rule (L57–59) itself has no ID.
- "Records carry indices, times, Events, Commands, and outcomes and nothing else" (L661–662) omits schema_version — a sixth category.
- A5 startup hole: Environment activation is effectful (ports live, events queue) before RunStarted can commit (the ordering is forced — the record carries the frozen start time); an empty Journal after a RunStarted commit failure evidences a run with real effects. State it.
- A2's scope vs concurrent Port processing of handed-off Commands is never stated in Laws.
- L1013 overclaims DET-RUN: "identical Journal bytes and exit" vs L676's discriminant-level equality.
- Naming: Regression (L706) vs TimeRegression (L575); registry latch-capacity and thread-count rows missing; Context/Engine/LiveCtx/SimCtx never get struct declarations in API blocks; "cleanly completed Journal" (L494) should say "a Journal whose tail has no sink failure"; state explicitly that Live Port panics are unsupervised under panic = "abort" (prevents a catch_unwind shell creeping into shipped code).
- Post-checkpoint window on the Stop path (publications discarded unobserved): the mechanism is honestly stated in RUN-CHECKPOINT, but the consequence — "a clean Stopped is not evidence of a clean final window" — deserves one derive sentence alongside L754–755.
What survived attack (verified)
- Graph liveness/completeness: every reachable (state × answer × batch-emptiness × latch) configuration has exactly one applicable edge; sketch matches tables 8/8. Stop+nonempty batch does dispatch before the checkpoint.
- ENV-SERIAL post-Err audit: no path calls anything but shutdown after an Err; start-Err path is vacuously fine.
- Token/witness machinery: affine witnesses, single constructors, PhantomData<fn() -> S> auto-trait claim, module-privacy boundary — all sound as Rust.
- Journal mechanics: poison set complete for Write+Flush; buffer sizing has no off-by-one (object = max+1 bytes fails at step 4, larger fails at step 2); encode-before-write is airtight.
- Sim internals: SIM-START vs the commitment table; round-robin/nondecrease arithmetic (set_next ≥ now + lowest-time selection ⇒ remaining arms ≥ new now); SIM-COMPLETION correctly scoped to app-error; on_command(Err) → latch → checkpoint chain consistent with "CommandsDispatched can be a run's final record".
- Live startup: "Any failure so far" (L834) covers mid-spawn failure; the gate guarantees "no Port code ever run".
- Appendix A: all 47 IDs present exactly once, correctly filed.
- Serialization plumbing: Serialize bounds project correctly through the Engine's where-clause; Never idiom valid; newtype-struct serde behavior as documented.
Bottom line: the skeleton (graph, latch, commitment algebra, token) is genuinely robust — the attacks that should have broken it didn't. The weaknesses concentrate at the claims layer: rows that promise more than their mechanism (RUN-GRAMMAR, DET-ENV, LIVE-THREADS), axioms cited past their quantifiers (A1, A3, A4), and a meta-rules section that exempts itself. Nearly everything above is a one-to-three-sentence fix; only findings 3 (journal the dispatch position) and 9–11 (rework the DET-ENV/replay framing) touch design substance.
