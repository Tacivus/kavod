## 0. Constraints restated (framework step 1, shared by every family)

Derived from §0, §1, §2, and the sections the patches touch. These are acceptance criteria;
every patch below was checked against each.

- **C1 — Four binding forms only.** API blocks (names, shapes, bounds, variant sets exact;
  doc comments bind behavior; listed derives required, further free unless a guarantee
  prohibits), guarantee rows (every normative rule outside a block or binding table is an
  ID'd row), binding tables (commitment table plus the Run's construction, startup, state,
  edge, record tables — exhaustive: work not listed does not happen), obligation rows
  (trusted). A rule in none of the four does not exist.
- **C2 — Prose has three jobs** (define / derive / justify) and faces the deletion test: if
  deleting a sentence changes an implementer obligation, it was a rule in the wrong clothes.
- **C3 — Placement.** Single-component facts live with the component; interaction facts live
  in the Run. Core sections never name an implementation.
- **C4 — Citations point backward**, IDs not section numbers; navigation pointers are the
  enumerated exemptions.
- **C5 — Implementation guarantees realize a named contract row** or define that
  implementation's Port-facing API.
- **C6 — Enforcement order.** Every non-Obligation ID is enforced (unrepresentable, asserted,
  or suite-tested); unrepresentable beats asserted beats tested; *the first available tier
  owns the rule's enforcement*. `ASSERT-INVARIANTS`: always-on, constant-time.
- **C7 — Glossary definitions are normative**; a *Define:* note binds the same way. The
  two-word rule: **fail/failure** means exactly "returned an Error."
- **C8 — One authority per fact** (A1 applied to the document itself): a fix may add
  citations and realizations but never a second normative owner.
- **C9 — No caller-supplied authority.** Within `RUN-ENFORCEMENT`'s boundary a transition
  requirement is never a value a caller can forget, reuse, contradict, or forge; no fix may
  add one.
- **C10 — No observable behavior change** unless the defect genuinely requires one; any such
  change is declared, not smuggled in as clarification.

## F1. Axiom glosses — A1, A2, A3 (§2, lines 144–146)

### 2. The defect, from first principles

The axioms are the document's foundational claims; every rule is declared "a consequence of
nine axioms." Three of the nine are falsified by the document's own detailed rows.

**A1** says every appearance of a fact outside its owner is "a read-only view of it." But a
*handler* calls `ctx.emit(command)` and thereby mutates the Run-owned batch buffer; a
*SimPort* calls `set_next`/`clear_next` and mutates the Environment-owned wakeup arm; a
*LivePort* calls `offer` and inserts into the Environment-owned fan-in queue. None of these
appearances is read-only. The design's actual discipline — already worded this way in
`APP-CONTEXT` ("the only capability Kavod supplies a handler") and `LIVE-COMPLETION` ("one
module-private, non-cloneable capability") — is: one owner, and others hold owner-defined
capabilities.

**A2** says "The turn ends at handoff." The binding graph disagrees: after the last handoff,
the same turn takes the checkpoint (`take_error`), commits `CommandsDispatched`, and commits
`TurnCompleted` — `RUN-CHECKPOINT` says "every *turn* that reaches `EffectsComplete` takes
the latch snapshot," which is after every handoff. An empty-batch turn has no handoff at
all. In the sim, `on_command` runs synchronously *inside* `dispatch`, inside the turn. The
sentence's true content is only its second half: the destination Port's processing of
handed-off Commands is outside the turn.

**A3** says "Every effectful operation has exactly one commitment point." `APP-STATE` says,
verbatim, "State mutation has no commitment point." Port-internal mutations during
`on_command` similarly stand without one (`PORT-STATE`, the sim's subordinate-effects rule).
The axiom's universal quantifier contradicts two binding rows.

**Witness (A2, concrete):** turn 5, batch of three Commands. Handoffs complete at instants
t1<t2<t3; `take_error` runs at t4>t3; `TurnCompleted(Continue)` commits at t5>t4. Under
"the turn ends at handoff," t4 and t5 lie outside turn 5 — yet `RUN-CHECKPOINT` and the
phase tables assign both to turn 5. Contradiction between an axiom and binding rows.

This is specification inconsistency, not a runtime failure: implementations follow the
detailed rows; the axioms mislead readers and reviewers (three of eight raised these).

### 3. Issue family

- grok H3 (A1 capability language) — central defect, A1.
- fable V12-15, grok H1, opus K18, sol M-06 (A2 turn-end) — central defect, A2.

- A4 and A9 overclaims — same family in the synthesis, already fixed in Tier 1; out of scope.

### 4. Fix shapes

**Shape A — scope each axiom in place** (recommended). Authority stays where it is: the
axiom row owns the foundational claim, scoped so the detailed rows are consequences rather
than exceptions. One new Glossary term (**Capability**) because the word becomes
load-bearing in an axiom and already appears undefined in `APP-CONTEXT` and
`LIVE-COMPLETION`. Nothing becomes representable/unrepresentable; no caller-supplied value.

**Shape B — leave the axioms, add a Laws prose paragraph glossing them.** Rejected: creates
a second normative home for each axiom's real meaning (violates C8), and the axioms — the
first thing every reviewer reads — stay false standalone, which is exactly the observed
failure mode.

### 5. Recommendation

Shape A. One owner per claim, no new mechanism, no behavior change.

## F2. Journal framing and claims (§6)

### 2. The defect, from first principles

The Journal writes one record as one JSON line: encode into a bounded buffer, check the
bytes, append a newline, write, flush. `JRN-FORMAT` claims "one record is one serde JSON
object plus one newline; line order is the sequence."

**(a) The framing hole — verified by execution.** The classification gate checks only that
the encoded bytes start with `{` and end with `}`. `serde_json`'s `RawValue` accepts and
re-emits verbatim a string with embedded raw newlines: committing a payload containing
`RawValue::from_string("{\n \"a\": 1\n}")` passes the gate and commits one record spanning
three physical lines. A JSONL reader then sees three "records," two of them garbage —
`JRN-FORMAT`'s own claim ("line order is the sequence") is false under `JRN-ENCODE`'s own
gate. The two rows contradict each other. Devon's decision: the one-line semantic is the
binding phrasing and enforcement follows from it (§0: the first available tier owns the
rule's enforcement — a bounded buffer scan is available).

**(b) The newtype claim — verified by execution.** The §6 Notes *Derive* says "newtype,
tuple, and unit structs do not [serialize as JSON objects]." False: a newtype is
serde-transparent — `struct W(BTreeMap<K,V>)` holding `{"k":1}` serializes as `{"k":1}`, an
object. The doc's own `EventIndex`/`Timestamp` rely on exactly this transparency ("both
serialize as transparent u64 JSON values," line 203).

**(c) Uncertain suffix scoped too narrowly.** `JRN-COMMIT` grants uncertain-suffix status
only "after a sink failure." Witness: a panic aborts the process (A8) after `write` returned
`Ok` but before `flush`; no sink failure was ever *returned*, yet bytes past the last
committed record sit in the sink as complete-looking lines. The §7 abort *Derive* (line 880)
already relies on the generalized reading; the rule doesn't state it.

**(d) "Sink failure" breaks the two-word rule.** The Glossary binds **fail/failure** as
"returned an Error; no further meaning." `JRN-POISON`'s "any sink failure" enumeration
includes `Ok(0)` and an over-reported count — outcomes that returned no Error. The term is
used in `JRN-COMMIT`, `JRN-POISON`, the Glossary's **Poisoned**, and a Notes *Derive*, with
a meaning the Glossary's own binding forbids. The enumeration needs one normative home.

**(e) Missing justification.** `Interrupted` poisons rather than retries — a deliberate
inversion of `std::io` convention with no *Justify:* note, so it reads as an oversight and
will be relitigated (deepseek already did).

### 3. Issue family

- opus K23, sol M-10 (RawValue framing) — central defect (a).
- opus K47, k3 N8, sol L-04 (newtype claim) — central defect (b).
- deepseek M4 (uncertain suffix) — central defect (c).
- fable V12-19 (`JRN-POISON` vs two-word rule) — central defect (d).

- Lossy serialization vs `CommandsPrepared`'s evidence claim (terra #3, sol M-11) — Tier 3,
  out of scope here.

### 4. Fix shapes

**(a)** Shape A — *semantic classification, enforced* (recommended; Devon's decision): the
rule says what a record *is* (one single-line JSON object); `JRN-ENCODE`'s classification
tests it, `NotAnObject` widens its doc-bound meaning, the scan is nonbinding mechanism, one
new `VERIFY-JOURNAL` case pins it. Invalid records become rejected-before-write (tested
tier). No new variant, so the API block's variant set is untouched. Shape B — extend
`TRUST-SERIALIZE` only (synthesis's minimal fix): rejected — leaves a Kavod-enforceable
format guarantee trusted, against C6's first-available-tier law. Shape C — new
`JournalError` variant (`NotOneLine`): rejected — changes the exact variant set for a case
whose handling is identical (Fatal), violating KISS.

**(d)** Shape A — one *Define:* for **sink failure** placed before the Guarantees (C4:
backward citation), `JRN-POISON` keeps only the Error mapping (recommended). Shape B —
stop using the word "failure" and enumerate inline in every row: rejected — three homes for
one enumeration (C8).

Other items have one honest shape each (correct the false claim; widen the rule; add the
note).

### 5. Recommendation

Shape A for (a) and (d); direct correction for (b), (c), (e).

## F3. Sim selection semantics (§9)

### 2. The defect, from first principles

`next_event` in the sim: check latch, check for armed Ports, check budget; select the armed
Port with the lowest time; advance `now`; clear the arm; call `step`; repeat until a `step`
returns an Event. Four gaps:

**(a) The tie-break is not one algorithm.** "Equal times by round-robin in frozen Slot
order" with a persistent cursor never says how the cursor picks among equal-minimum arms.
Witness: Slots {0, 1, 2}, cursor at 2, Slots 0 and 2 both armed at t=100 (the minimum). A
scan-from-cursor-with-wrap implementation selects Slot 2; an absolute-Slot-order
implementation selects Slot 0. Both satisfy every written word; they produce different
candidates, different traces, byte-divergent Journals. Two conforming sims disagree —
specification incompleteness, not a runtime bug.

**(b) The latch path is stated only by citation.** Tier 1 gave `SIM-DISPATCH` its explicit
latch-first sentence; `SIM-SELECT` still says only "checks … the latch (`ENV-LATCH`)"
without saying what the check *does* (return the pending Error as this call's `Err`,
nothing selected or consumed).

**(c) Subordinate effects are named for one of three `Err` paths.** The commitment table's
`next_event` row says "subordinate effects the implementation names stand" — the
implementation must *name* them. The sim names them only for `step(Err)`. Witness: budget
2; selection 1 steps Slot A at t=100, `step(None)` — `now`=100, arm cleared, budget 1;
selection 2 steps Slot B at t=150, `step(None)` — `now`=150, budget 0; the third check
fails: `Err` (exhaustion). `now`=150 and two cleared arms stand — but no rule names them
for this path, so a strict reader may claim they roll back (they cannot) or that the sim
breached its naming obligation. Same for mid-selection `SIM-COMPLETION`.

**(d) Arms start in no stated state**, though the replay derive and `SIM-COMPLETION` both
assume disarmed.

**(e) Ended-Port arms — sharpened by Tier 1.** `SIM-LIFECYCLE` now binds "no method may be
invoked in `Ended`." A stale arm left by a Port whose `on_command` returned `Err` would, if
ever selected, force `step` on an `Ended` Port — a binding-row breach. It is in fact
unreachable: a lifecycle Ends mid-run only through an `Err`; from `start` the run never
selects; from `step` the `Err` returns through `next_event` and `ENV-SERIAL` permits only
`shutdown` after; from `on_command` the Error is pending in the latch and every later
observing operation returns it before selection. Nothing states this, so a reader cannot
tell whether `SIM-SELECT` needs an `Ended` guard.

### 3. Issue family

- grok M3, opus K52 (tie-break) — central defect (a).
- grok M4 (latch by citation) — central defect (b).
- fable V12-08, k3 G6, opus K53 (subordinate effects, three paths) — central defect (c).
- sol M-07 (initial disarm) — central defect (d).
- grok M2 (dead arms; grok itself proved unreachability) — central defect (e), upgraded by
  Tier 1's `SIM-LIFECYCLE`.
- deepseek M8 (cursor must be recorded in the trace) — rejected by the synthesis; not
  re-raised: the cursor is a deterministic function of config + trace, and (a)'s fix is
  what makes that function single-valued.

### 4. Fix shapes

**Shape A — everything into `SIM-SELECT`, one row** (recommended): the selection function,
the explicit latch consequence, and one shared subordinate-effects clause quantified over
every `Err` the call returns. Unreachability of stale arms becomes a *Derive:* (it is a
consequence, not a new rule — C2) plus one always-on mechanism assert (`ASSERT-INVARIANTS`,
constant-time, defense against the argument being invalidated by later edits).

**Shape B — new IDs** (`SIM-CURSOR` for the tie-break, `SIM-EFFECTS` for subordinate
effects): rejected — splits one operation's semantics across three rows with no independent
enforcement or citation need (KISS; C8's fewest-homes principle).

**Shape C — clear the arm on lifecycle `Ended`** (make stale arms impossible rather than
unreachable): rejected — adds mechanism for a state already proven unreachable (YAGNI), and
would silently mask a real Kavod bug the assert is designed to catch.

### 5. Recommendation

Shape A.

## F9. Replay derive scoping (§9 Notes, lines 1132–1135)

### 2. The defect, from first principles

The derive states three preconditions for byte-equal replay: matching origin, arming each
recorded stamp in order and answering each `step` with the recorded Event, and sufficient
budget. It is recipe-shaped, and the recipe provably diverges. Witness (verified in the
review round): two Slots, both armed at t=500. In the original run, Slot B's arm was placed
by `on_command` during turn 3; in the replay, the replay Port arms B at `start`. Every
recorded stamp is armed in order, every `step` answered with the recorded Event, budget
ample — all three preconditions hold. But the cursor's position at the tie differs
(arm *placement* changed which selections preceded the tie), a different Slot wins, and the
Journal diverges at the next `EventAccepted`. Arm placement is behavior no recorded
artifact captures. The adjudication: "needs" is correct as necessity; the note must say the
three are not sufficient.

### 3. Issue family

- grok H6 (called it false), k3 G8 (under-covering) — central defect; the fable defense
  ("necessity") holds and is incorporated.

### 4. Fix shapes

**Shape A — scope the note in place** (recommended): necessary-not-sufficient, the two
extra conditions (arm placement; Error presence at trace position for failure runs), and
the single-Port discharge.

**Shape B — record arm placement in the trace** so the three become sufficient: rejected —
observable format change (new trace/record content) to strengthen a user-wiring
convenience note; the synthesis's deepseek-M8 rejection already establishes internal
scheduling state stays out of the trace.

### 5. Recommendation

Shape A.

### 6. Patch

**Patch F9.1 — replay derive (lines 1132–1135).**
Old:
```
*Derive:* byte-equal replay of a recorded run needs three preconditions: the
configured origin equals the recorded `RunStarted` logical time; the replay Port arms
each recorded stamp in order and answers each selected `step` with the recorded Event;
and the step budget covers every acquisition.
```
New:
```
*Derive:* byte-equal replay of a recorded run needs three preconditions: the
configured origin equals the recorded `RunStarted` logical time; the replay Port arms
each recorded stamp in order and answers each selected `step` with the recorded Event;
and the step budget covers every acquisition. The three are necessary, not sufficient:
equal-time selection depends on the cursor, and the cursor on when each arm was placed —
placement no recorded artifact captures — so a multi-Slot replay must also reproduce
each arm's placement, and a failure run must reproduce each Error's presence at its
trace position. A single-Port run with no Error in its trace needs the three alone.
```
